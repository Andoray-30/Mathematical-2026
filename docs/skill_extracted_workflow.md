## 一、三阶段协作流程

### 总览

```
建模分析 → 代码实现 → 论文撰写
 (大脑)      (双手)      (喉舌)
```

| 阶段 | 角色 | 核心任务 | 产出 |
|:----:|:----:|---------|------|
| ① | 建模手 | 分析题目、选择模型、设计算法、建立术语规范 | 分析报告 + 术语表 + 前置合同 |
| ② | 编程手 | 编写代码、求解结果、Figure Contract 可视化 | 代码 + SVG/PNG图表 + HTML面板 |
| ③ | 论文手 | 构建论证、Claim-Evidence 映射、章节模板写作、自审 | 完整论文（.docx） |

### 阶段依赖关系

- 建模手产出 → 编程手只读参考（分析文档、术语表）
- 编程手产出 → 论文手使用（figures/、results/）
- 建模手产出 → 论文手使用（模型选择依据、文献、术语表）

## 二、Model Contract（前置合同）

在开始建模分析之前，必须先建立 Model Contract。

### 2.1 核心结论

用一句话写出这道题必须回答的核心问题。

> B题示例："建立AI生成内容的质量评估模型，对8张图片和1段视频进行多维度质量评价与参数优化建议。"

### 2.2 子问题-模型映射表

| 子问题 | 选用模型 | 该模型承担的证据角色 | 备选方案 |
|-------|---------|-------------------|---------|
| 子问题A | 模型X | 提供定量预测结果 | 模型Y |
| 子问题B | 模型Z | 提供多因素综合评价 | 模型W |

**防冗余原则**：如果去掉某个模型后，核心结论仍能从其他模型的求解结果中完整推导出来，则该模型是冗余的。每个模型必须承载独特且不可替代的分析维度。

### 2.3 方案选择评审

| 评审项 | 内容 |
|-------|------|
| 候选方案 | 每个子问题列出 2-3 个候选模型 |
| 选择理由 | 为何选定当前模型（数据适配性 / 复杂度 / 可解释性） |
| 潜在风险 | 该模型的局限性、数据要求、计算成本 |
| 备选方案 | 如果首选方案失败，使用什么替代 |

### 2.4 交付规格

| 交付物 | 接收方 | 说明 |
|-------|--------|------|
| 模型公式与推导 | 编程手 | 精确的数学表达式、参数含义、取值范围 |
| 算法步骤与伪代码 | 编程手 | 详细的求解流程、输入输出格式、边界条件 |
| 可视化需求清单 | 编程手 | 图表类型、数量、核心信息 |
| 模型选择依据 | 论文手 | 理论文献支撑、对比分析理由 |
| 参考文献 | 论文手 | 完整引用格式 |
| 术语表 | 论文手 | 中英文术语对照、符号定义 |

## 三、建模手工作流程

### 第零步：附录检查（必须最先执行）

检查工作目录中的附件文件夹，使用 pdf skill 读取PDF题目，使用 xlsx skill 读取Excel数据。

### 第一步：题目理解

| 信息类型 | 说明 |
|---------|------|
| 问题背景 | 题目的实际背景和应用场景 |
| 问题类型 | 优化、预测、评价、分类等 |
| 数据情况 | 已知数据、待求数据、数据特点 |
| 约束条件 | 各种限制条件和边界条件 |
| 目标要求 | 需要解决的具体问题 |

### 第二步：模型选择

**三原则**：
1. 能用初等方法解决的就不用高等方法
2. 能用简单方法解决的就不用复杂方法
3. 能用被更多人看懂、理解的方法就不用只能少数人看懂、理解的方法

**评价问题推荐模型**：AHP、熵权法、TOPSIS、模糊综合评价

### 第三步：算法设计

1. 求解思路：详细的求解步骤和方法
2. 算法流程：清晰的算法流程图或步骤描述
3. 评价指标：模型好坏的评判标准
4. 参数设置：关键参数的选择和调整方法

### 第四步：术语规范

建立术语表格，确保全文术语一致性。

## 四、编程手工作流程

### 第一步：理解需求

读取建模分析文档，确认编程语言（Python），理解题目要求。

### 第二步：环境检查

检查 Python 版本和必需包：numpy, pandas, matplotlib, scipy, sklearn, statsmodels, openpyxl。

### 第三步：代码设计与可视化规划

三类图表规划：
1. **原始数据可视化**（EDA）：数据分布、相关性分析、时序趋势
2. **中间产物可视化**：收敛曲线、模型对比、参数分析、误差分析
3. **最终结果可视化**：最终方案对比、综合排名/评价

每类至少 1 张图，每题至少 3-5 张图。

### 第四步：代码实现

编写代码 → 运行代码 → 检查报错 → 修正 → 重新运行 → 验证结果。

### 第五步：结果验证

结合题目要求和建模分析文档验证结果。

### 标准文件结构

```
project/
├── data/                    # 数据文件夹（只读）
├── 问题X_求解.py            # 各问题的求解代码
├── results/                 # 结果输出文件夹
├── figures/                 # 可视化图表文件夹
│   ├── figure1.svg          # 可编辑矢量格式
│   ├── figure1.png          # PNG预览（dpi=300）
│   └── 图表面板.html        # 图表可视化导航面板
└── README.md                # 项目说明文档
```

## 五、论文手工作流程

### 第一步：收集资料

收集建模分析文档、代码和结果、题目文件、前置合同。

### 第二步：论证构建 (Argument Building)

**一句话论证模板**：
```
针对 [问题/系统]，我们采用 [方法/模型] 实现了 [进展/结果]，
通过 [证据] 支撑，适用范围为 [边界条件]。
```

### 第三步：Claim-Evidence 映射表

| 主张 (Claim) | 证据 (Evidence) | 位置 | 状态 |
|-------------|----------------|------|------|
| 模型X准确率高 | 图3：对比柱状图，准确率95% | 第5章 | ✅ 已有证据 |
| 模型X稳定性好 | 表4：10次运行标准差<0.5 | 第6章 | ✅ 已有证据 |

### 第四步：论文规划

应用论证框架，确定格式、章节、内容分配、图表规划。

### 第五步：论文撰写

撰写流程：
1. 构建论证框架
2. 使用 docx skill 读取论文模板
3. 根据论证框架创建论文框架
4. 按章节填充内容
5. 插入编程手生成的图片
6. 对每张图片进行详细解释和分析（≥100字）
7. 段落流检查 + 去AI味检查 + 格式规范检查

## 六、Claim-Evidence 映射

### 核心论证要素

| 要素 | 问题 | 示例 |
|------|------|------|
| **核心主张** | 这篇论文到底证明了什么？ | 本文模型在预测精度上优于所有基线 |
| **证据** | 用什么数据或结果支撑？ | RMSE降低15%，R²从0.82提升到0.91 |
| **边界** | 在什么条件下结论成立？ | 样本量>50时效果显著 |
| **意义** | 这项工作带来了什么？ | 为实时预测提供了可行的方案 |

### 证据阶梯（结果分析部分）

```
system（系统/工作流程）
  → validation（验证）
    → main result（核心结果）
      → comparison（对比分析）
        → analysis（机制/深入分析）
          → application（应用/推广）
```

## 七、自审框架（四轮审查）

### 第一轮：论证逻辑审查

逐条检查核心主张是否都有证据支撑：
- 悬空主张：结论没有数据支撑 → 添加引用到对应图表
- 证据不足：一个图表支撑了过多结论 → 补充更多证据
- 跳跃逻辑：A→C 跳过了 B → 补充中间推理步骤
- 循环论证：用结论本身证明结论 → 重新组织论证路径
- 反方测试：站在评阅老师角度，对每个结论问"反面是什么？有反驳证据吗？"

### 第二轮：章节结构审查

- 摘要六要素：context → gap → approach → result → implication → boundary
- 引言五要素：field scale → bottleneck → prior attempts → gap → present study
- 结果证据阶梯：system → validation → main result → comparison → analysis
- 讨论五要素：advance → evidence → relation → constraints → future

### 第三轮：表述质量审查

- AI味检查：扫描"此外"、"关键的"、"深入探讨"等AI高频词
- 数据准确性：所有数值前后一致，单位标注正确
- 公式/图表/参考文献编号一致

### 第四轮：格式规范审查

- 纸张大小、页边距、字体、行距、页码
- 图有图号+图题（图下方），表有表号+表题（表上方）
- 三线表格式
- 参考文献格式统一

### 自审结论

| 结论 | 含义 | 行动 |
|------|------|------|
| ✅ 通过 | 所有检查项通过 | 可交付 |
| ⚠️ 有条件通过 | 非关键项未通过 | 标记改进项后交付 |
| ❌ 不通过 | 存在论证漏洞或关键格式问题 | 修复后重新审查 |
